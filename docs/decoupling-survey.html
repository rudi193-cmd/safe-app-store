The real duplication: 3 copies of signed-header construction

  • sap/core/gate.py — _signed_header() with local _FIELD_NAMES tuple
  • gatefirst/identity.py — imports _SIGNED_FIELDS from willow_gate
  • gazelle_gate.py — imports wg._SIGNED_FIELDS for build_header()

All three build the same 13-field HMAC-SHA256 signed header independently.

Three separate signing mechanisms, no shared interface

  • willow_gate — HMAC session headers (runtime auth)
  • stores/sap_gate.py — Ed25519 manifest signing (build attribution)
  • willow_gate.custody — hash-chained checkpoint sealing (promotion)

Manifest permissions are disconnected from runtime gates

The manifest permissions list is free-form tags never consulted at runtime. Gate authorization uses hardcoded role tables baked into each app's gate module. Two independent sources of truth.

Next action: Expose build_signed_header() as a public helper so callers stop importing _SIGNED_FIELDS. Define AuthGate Protocol (check_in/authorize_tool/check_out). The 13 files using sap.core.gate's public surface need no change — they're already decoupled. Sequence: gazelle first (single chokepoint), then gatefirst (comparison slice).

BUG ai-game-master store_scope type error fixed

store_scope was a bare string "user-{uuid}/ai-game-master/**" instead of a list. Gate treats a string as [] (deny-all), silently nullifying all declared permissions. Fixed to ["user-{uuid}/ai-game-master/**"]. No other manifest had the same bug.

Execution order

Each priority is independent — they can run in parallel. But sequencing within P4 matters (gazelle before squirrel). P3 (lattice) is the fastest win. P0 (safe_integration) is the highest leverage. P5 (manifests) is the least urgent — declaration, not enforcement.
