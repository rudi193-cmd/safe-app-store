SAFE App Store · fleet architecture

The Table

The game apps don't merge. The Game Master is a three-layer spine — and only the middle layer is missing.

Five folders in this store already touch games. Read as running code rather than READMEs, each one turns out to supply a different layer of what an AI Game Master needs — and the house built the two hard layers and skipped the connective tissue in between. This is the map of that spine: what exists, what's missing, and the smallest slice that proves the whole thing runs.

02

The thin waist

Library-clean, zero dependencies. The one keystone artifact — write it once.

game_session.py — the protocol every game implements
class GameSession(Protocol):
    def reset(self, seed) -> Observation      # deal the opening
    def observe(self, seat) -> Observation    # what this seat can see
    def legal_moves(self, seat) -> list[Move]
    def step(self, seat, move) -> Observation  # advance the state
    def is_terminal(self) -> bool
    def result(self) -> Result             # winner / scores

04

Two house rules the standing law forces

And they're good — the architecture is pre-shaped to obey them.

Sealed fleet decision

The model proposes; a person seals.

The GM may drive play and roll dice, but sealing canon stays human — already enforced by ai-game-master's NOT_A_PERSON guard and playgate's reason-bearing human grant.

Rediscovery tax

Reuse the ledger — don't rebuild it.

The hash chain already exists in verify_ledger.py; Nestor is the fleet's seal. The GM reuses that memory layer. The loop was scoped in DECISION.md §7 and shelved — not undocumented.

The proof

Run a bureau game through the GM, then run ai-game-master's own verify_ledger.py over the produced db — the chain verifies. The smoosh, demonstrated end to end.

Where it lives: its own playground app — working name apps/the-table — that injects the others' library surfaces (imports bureau's Session, writes ai-game-master's ledger) without ever reaching into another app's data lane. Each folder stays in its own lane; the GM is the thin new organ that sits between them. game-lab has the games, ai-game-master has the memory, and the GM loop is the seam neither built.
